===== ble-doctor  =====
Cross-platform BLE diagnostics and security CLI

Usage: ble-doctor [OPTIONS] <COMMAND>

Commands:
  scan          Scan for BLE devices
  analyze       Analyze a capture or device
  sniff         Ingest a BLE sniffer (Sniffle) stream and judge MAC rotation; needs sniffer hardware for --device
  fingerprint   Device fingerprint: LE+GATT profile (+ SDP/LMP on Linux)
  fix           Print (or copy) a prompt for a coding agent from one finding or the whole scan
  probe-writes  Probe writable characteristics (EMPIRICAL: connects without bonding and writes)
  install       Write an agent skill, Cursor rule and AGENTS.md block into a repo
  read-values   Read characteristic values on non-SIG services (lists length + preview only)
  ci            CI helpers
  dfu           Probe DFU surface (EMPIRICAL buttonless probe: writes to the device without bonding)
  doctor        Diagnose the local BLE environment
  mcp           Run the MCP server
  recon         Recon a target (native GATT inventory)
  ctf           CTF helpers (own-gear / CTF scope only; never reachable via `mcp`)
  baseline      Baseline snapshots
  handoff       Export a handoff bundle
  rules         Inspect rules
  why           Explain a finding (rule doc, plus the finding from a report JSON)
  mitm          GATT MITM: clone the target as a peripheral and relay+log traffic to/from it (Linux + 2 adapters + peripheral mode only; EMPIRICAL/active)
  shell         Interactive shell over a live device or a capture
  explore       Full-screen explorer over a live device or a capture
  serve         Run a read-only REST API + event stream over GET /scan and GET /events
  help          Print this message or the help of the given subcommand(s)

Options:
      --adapter <ADAPTER>  Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
  -h, --help               Print help
  -V, --version            Print version
===== ble-doctor scan =====
Scan for BLE devices

Usage: ble-doctor scan [OPTIONS]

Options:
      --adapter <ADAPTER>        Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
      --face <FACE>              Output face [default: rich] [possible values: plain, rich, compact]
      --target <TARGET>          Target address / identifier / name (or set BLE_DOCTOR_TARGET) [env: BLE_DOCTOR_TARGET=]
      --theme <THEME>            mono | clinical | contrast (default: the doctor's own theme)
      --timeout <TIMEOUT>        Scan duration in seconds [default: 5]
      --mtu <MTU>                Request exactly this ATT MTU from --target (a BLE address; Linux only)
      --as-address <AS_ADDRESS>  Connect to --target presenting this BLE address (LE Set Random Address; Linux only)
      --color <COLOR>            [default: auto] [possible values: auto, always, never]
      --json                     Emit the doctor/1 JSON envelope (needs --target)
      --score                    Print only the score number
      --tui                      Show the findings in an interactive terminal UI (needs --target)
      --headless                 Plain text, no color: for CI and pipes
      --sarif <SARIF>            Write a SARIF 2.1.0 report to this file (needs --target)
      --baseline <BASELINE>      Diff findings against a saved doctor/1 `--json` report; exit 3 if NEW failures reach --fail-on
      --fail-on <FAIL_ON>        Exit 1 (3 with --baseline, new findings only) when a finding is at or above this severity [default: high] [possible values: info, low, medium, high, critical]
      --sort <SORT>              Sort the device list (bare scan only; printed live as devices are seen, then once more in this order) [possible values: rssi, name, address]
  -h, --help                     Print help
===== ble-doctor analyze =====
Analyze a capture or device

Usage: ble-doctor analyze [OPTIONS] <CAPTURE>

Arguments:
  <CAPTURE>  Path to a btsnoop/pcap capture

Options:
      --adapter <ADAPTER>    Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
      --face <FACE>          Output face [default: rich] [possible values: plain, rich, compact]
      --json                 Emit the doctor/1 JSON envelope
      --sarif <SARIF>        Write a SARIF 2.1.0 report to this file
      --theme <THEME>        mono | clinical | contrast (default: the doctor's own theme)
      --baseline <BASELINE>  Diff findings against a saved doctor/1 `--json` report; exit 3 if NEW failures reach --fail-on
      --color <COLOR>        [default: auto] [possible values: auto, always, never]
      --fail-on <FAIL_ON>    Exit 1 (3 with --baseline, new findings only) when a finding is at or above this severity [default: high] [possible values: info, low, medium, high, critical]
      --irk <IRKS>           An IRK you already hold (32 hex chars, same byte order as an Identity Information PDU), to resolve Resolvable Private Addresses in the capture against (repeatable). Improves the mac_rotation verdict: rotating addresses that all resolve to one IRK are one device's RPA, not several distinct ones
      --score                Print only the score number
      --headless             Plain text, no color: for CI and pipes
  -h, --help                 Print help
===== ble-doctor sniff =====
Ingest a BLE sniffer (Sniffle) stream and judge MAC rotation; needs sniffer hardware for --device

Usage: ble-doctor sniff [OPTIONS]

Options:
      --adapter <ADAPTER>        Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
      --device <DEVICE>          Serial/USB sniffer port (e.g. /dev/ttyACM0)
      --from-file <FROM_FILE>    Saved Sniffle text dump to parse instead of live capture
      --json                     Emit JSON
      --write-pcap <WRITE_PCAP>  Also write the session's advertising frames as a pcap (Wireshark/crackle can open it)
      --fifo <FIFO>              Stream frames live to this named pipe as they're captured (`mkfifo` it first, then `wireshark -k -i <path>`); blocks until a reader opens it, like `btlejack -w`
  -h, --help                     Print help

===== ble-doctor fix =====
Print (or copy) a prompt for a coding agent from one finding or the whole scan

Usage: ble-doctor fix [OPTIONS] [ID]

Arguments:
  [ID]  Finding rule id or fingerprint prefix (default: every finding)

Options:
      --adapter <ADAPTER>  Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
      --config <CONFIG>    doctor.toml (default: <path>/doctor.toml when present)
      --fail-on <FAIL_ON>  Exit 1 when a finding is at or above this severity [default: high]
      --copy               Also copy the prompt to the clipboard
      --from <FROM>        Take the findings from this saved `scan --json` report instead of scanning
      --agent <AGENT>      Hand the prompt to this coding agent instead of printing it [possible values: claude, codex, cursor]
      --yolo               With --agent: skip the agent's approval prompts (the scanned text is untrusted)
  -h, --help               Print help

===== ble-doctor install =====
Write an agent skill, Cursor rule and AGENTS.md block into a repo

Usage: ble-doctor install [OPTIONS]

Options:
      --adapter <ADAPTER>
          Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere

      --dir <DIR>
          Repository to write into
          
          [default: .]

      --agent <AGENT>
          One agent only (default: all)

          Possible values:
          - claude
          - cursor
          - codex:    Codex and opencode both read AGENTS.md
          - opencode

      --agent-hooks
          Also add a Claude Code PostToolUse hook that scans changed files after edits

      --print-only
          Print the files instead of writing them

  -h, --help
          Print help (see a summary with '-h')

  write-then-read  Write a value, then read a (possibly different) characteristic back

      --adapter <ADAPTER>  Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere

===== ble-doctor ctf brute =====
Write 0x00..=0xff to --char one byte at a time, reading --read-char back after each write, until the read-back contains --contains

Usage: ble-doctor ctf brute [OPTIONS] --target <TARGET> --char-uuid <CHAR_UUID> --read-uuid <READ_UUID> --contains <CONTAINS>

Options:
      --adapter <ADAPTER>      Local Bluetooth adapter (e.g. hci0). Linux only; ignored elsewhere
      --target <TARGET>        Target address / identifier / name (or set BLE_DOCTOR_TARGET) [env: BLE_DOCTOR_TARGET=]
      --char-uuid <CHAR_UUID>  Characteristic UUID to brute-write
      --read-uuid <READ_UUID>  Characteristic UUID to read back after each write
      --contains <CONTAINS>    Stop once the read-back value contains this substring (ASCII)
      --timeout <TIMEOUT>      Scan/connect timeout in seconds [default: 5]
  -h, --help                   Print help
